# Что приготовить

Поиск рецептов по TheMealDB и личная коллекция с авторизацией:
найди блюдо по названию или категории, сохрани в избранное, создавай свои рецепты.

**Стек:** React 19 + TypeScript + Vite · TanStack Query · Zustand · React Router · Supabase (Postgres + Auth + RLS) · Tailwind CSS 4 · Vitest

**Прод:** https://recipe-app-rk.netlify.app/

## Фичи

- Поиск по названию: debounce 300 мс + отмена устаревших запросов через AbortSignal
- Фильтр по категориям: второе семейство ключей кэша, keepPreviousData при переключении
- Избранное: хранится в Postgres под RLS, оптимистичный toggle с откатом при сбое
- История просмотров: device-local by design — привязана к устройству, не к аккаунту
- Свои рецепты: создание (react-hook-form + Zod) и удаление с подтверждением
- Авторизация: регистрация, вход, выход, защищённые маршруты
- 40+ тестов: мапперы, границы Zod-схемы, debounce на fake timers, компоненты

## Архитектура

- Серверное состояние — TanStack Query: семейства ключей
  `["meals", term]`, `["category", name]`, `["meal", id]`,
  `["my-recipes", user.id]`, `["favorites", user.id]`
- Клиентское глобальное — Zustand (только история); избранное переехало на сервер
- Граница доступа — RLS: политики `using` / `with check (auth.uid() = user_id)`,
  `user_id` ставится сервером через `default auth.uid()` и не приходит с клиента
- Внешние пробы write-path: insert с чужим `user_id` → 403 (RLS 42501);
  `meal_id` из пробелов → 400 (check 23514); дубль → 409 (PK 23505 держит дабл-клик);
  insert без `user_id` → 201, автор подставлен сервером
- Сетевые паттерны проверены снаружи: сабмит формы = ровно один POST + один GET
  после инвалидации; открытие своего рецепта = 0 новых запросов
